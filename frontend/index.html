Live
Static rule fallback active. Scoring service unreachable — decisions use amount and recipient novelty thresholds only. Every transaction below is still logged for rescoring once the model is back.
Pass
Goes through with no friction. Nothing shown to the customer.
Step up
Extra verification required (SMS or voice confirm) before the transfer completes. Friction, not a block.
Hold
Paused and sent for review before release. The highest friction tier, reserved for the clearest cases.
Fallback
The backup rule based decision method used when the ML scoring service is unreachable.
Degraded
The system's state while it's running on the fallback rule instead of the live model.
Kill switch
The button above. Manual here, would trip automatically if the model service timed out.
(rule) tag
Marks a decision made by the fallback rule, not the ML model.
Rescoring
Scoring a fallback decision again once the real model reconnects. See any flagged row's detail panel.
